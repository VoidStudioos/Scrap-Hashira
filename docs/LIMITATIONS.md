# Current media limitations

See [MEDIA_0.3.0.md](MEDIA_0.3.0.md). Direct videos are signature-checked only. Blob/stream assembly and automatic click-only branch traversal are not implemented. Native Windows and authenticated target acceptance remain unverified.

# Known limitations — 0.2.2

1. **Native sign-off remains open.** The current native acceptance retry fails during full Chrome startup with SIGSEGV before the extension loads. A no-extension control and even the browser's version command also crash. Earlier delivery observed a singleton-socket restriction. The precise current startup cause has not been established. Native manifest installation, Chrome Downloads/Side Panel/Offscreen APIs, forced MV3 termination, Chrome restart and Windows interaction remain unverified; the successful headless-shell harness cannot replace these checks.
2. **Heuristic compatibility.** Generic detection and optional adapter hints are implemented, not universal guarantees. Fixtures represent several layouts; production Shopify/Magento/PrestaShop/OpenCart variations were not broadly tested. Unusual sites need profiles and preview review.
3. **Rendered main document.** Closed shadow roots, cross-origin frames, canvas-rendered text, OCR, browser-internal pages and inaccessible server source are outside the current extractor. Virtualized lists may recycle elements; bounded scrolling is not a guarantee of complete virtual-list capture.
4. **Bounded interaction.** User-configured scrolling and Load More clicks operate the current rendered page. There is no arbitrary click automation, click-through challenge handling, hidden API interception or session/password export. Sorting state is the page's current state; the extension does not automatically enumerate every sorting permutation.
5. **Image candidates.** The engine downloads selected advertised candidates; it does not discover unadvertised originals or claim a global highest resolution. Every candidate remains visible, including thumbnails/ambiguous images. Multiple advertisements can refer to identical bytes; the Blob store deduplicates them. Concurrent identical fetches can still result in separate Chrome file submissions before the first completes.
6. **Browser image validation.** Raster decode validates the browser-decodable image/first frame; it is not exhaustive forensic validation of every byte/frame of an animated file. SVG is parsed and rejects active content. Very large decoded image dimensions can use more memory than compressed-byte budgets suggest.
7. **Resource access.** Redirecting resource fetches fail visibly rather than following unapproved redirects. Browser-session navigation usually preserves the user's authorized session; sites with additional referrer, cookie partitioning or signed-download restrictions may block background resource fetching. Blob URLs belonging to a page are not copied after the page closes; ordinary HTTP(S) and bounded inline data image URLs are supported.
8. **Documents/APIs.** Optional document capture currently supports same-origin accessible PDF files. API capture is limited to explicit same-origin JSON GET paths, up to ten paths and 2 MB per response, with simple array-record inference. It does not spy on all XHR traffic or obtain inaccessible endpoints.
9. **Resume and timing.** Atomic checkpoints prevent partial page commits; in-flight pages can finish while a pause is requested. Alarm scheduling is controlled by Chrome, so closed-panel throughput may be slower than the configured short request delay. Job concurrency is per batch, not an assertion that no two authorized requests overlap. A completed job's files are not recreated automatically after intentional deletion.
10. **Export size.** XLSX, CSV and JSZip exports require bounded in-memory materialization. Exports now require a non-running job with no in-flight page/fetch checkpoint. Estimated memory limits reject oversized jobs; streaming JSONL is the large-dataset alternative when the File System Access API is available. There is no streaming ZIP writer or direct arbitrary-folder filesystem permission.
11. **Local storage.** IndexedDB is not an encrypted vault or cloud backup. Clearing extension data/uninstalling removes stored datasets. Profile path/extension identity changes can lead to a different data store. Export before moving or uninstalling.
12. **Selectors and language.** Automatic CSS and fallback XPath are best-effort; page redesigns can invalidate them. Core UI supports Persian/RTL, while some diagnostics, technical controls and data-derived labels remain English.
13. **Robots policy.** The parser supports agent groups, allow/disallow, wildcard and end matches. It is not a complete policy/compliance engine, and robots.txt does not grant access. Configure delays to satisfy the site's applicable rules; unsupported access requirements must be handled manually.
14. **Distribution.** This is an unpacked extension build. It has not been submitted to or reviewed by the Chrome Web Store. No production deployment or account changes were performed.

15. Semantic classification is deterministic inference, not guaranteed understanding or OCR. Numeric identifiers without labels can be ambiguous and retain confidence/evidence. Closed/unloaded tree branches are not invented or automatically clicked. A JavaScript-only image action without an accessible source URL is reported as interaction-required. Semantic category/type exports apply to newly captured pages; old snapshots without semantic metadata must be captured again. Category folders link to shared canonical image files instead of duplicating image bytes.

- Open-branch capture requires the user to open each JavaScript-only branch and supply its label path. Open a lightbox in the site first if its full image has no exposed URL. This mode captures the rendered top-level page. Embedded frames and images without a supported accessible source are outside this mode.
